# Прототип на Java 11

Проверка решения [ADR-0007](architecture/adr/0007-technology-stack.md) и перенос правил из текущего сервиса ([diploma_supplement_service](https://github.com/nikita-konkin/diploma_supplement_service)). Состояние на 01.10.2026.

## Что умеет прототип

- Веб-страница на встроенном Tomcat 10.1. В настольном режиме программа слушает только 127.0.0.1 и сама открывает браузер.
- Импорт ведомости «Деканата» (`.xls` или `.xlsx`) и, по желанию, учебного плана — в Excel или в PDF, сохранённом из «Планов». Семестры складываются, з.е. берутся из плана, для оператора — таблица пометок. Результат сохраняется в промежуточной зоне SQLite.
- Шапка учебного плана: код и наименование направления подготовки отдельно от профиля (B-25), квалификация, форма и срок обучения, год набора.
- Учебные планы в базе по годам набора и формам, с редакциями (`/plans`, [ADR-0008](architecture/adr/0008-curricula-by-editions.md)):
  - загрузка через предпросмотр;
  - проверка контрольных сумм;
  - сравнение с ближайшим планом программы;
  - правка с сохранением новой редакцией;
  - «Создать на основе» — для планов, которые есть только сканом.
- Выпуски (`/graduations`, [ADR-0009](architecture/adr/0009-graduations-matching-registry.md)):
  - загрузка ведомости и сведений группы; форма обучения и год набора берутся из шапки ведомости, план выбирается по ним;
  - сопоставление студентов и предметов ведомости с элементами плана в промежуточной зоне, выбор оператора там, где автоматически нельзя;
  - картотека выпускников с проверкой и XML 3.5.1 из картотеки.
- Тестовый лист калибровки принтера (PDF, A4 альбомный) с поправками вправо и вниз в миллиметрах.
- XML «ФайлОбменаКиберДиплом» 3.5.1 из сводной таблицы и сведений о студентах: переходный период, пока печатает КиберДиплом. Кнопка «Заполнить из плана» берёт 9 из 10 полей формы из учебного плана; председателя ГЭК оператор вписывает сам.

## Результаты по критериям ADR-0007

Замеры сделаны в Linux-контейнерах OrbStack на Mac (arm64 и x86-64 через Rosetta). На каждом прогоне 9 запросов: трижды импорт реальной ведомости (141 КБ) с учебным планом, тестовый лист и XML по реальной сводной.

| Критерий | Требование | Результат |
|---|---|---|
| Запуск без установки | рантайм в поставке | урезанный jlink-рантайм 51 МБ (arm64) / 56 МБ (x86-64) и программа 39 МБ |
| Время запуска | меньше 5 с | 0,3 с (arm64), 0,7 с (x86-64 через Rosetta) |
| Память | меньше 300 МБ | пик 243 МБ (arm64) и 276 МБ (x86-64) с настройками запускателя: куча 128 МБ, последовательный сборщик мусора, только компилятор C1. С настройками JVM по умолчанию — 402 МБ, поэтому запускатель их задаёт |

## Перенесённые правила

| Что | Откуда | Куда |
|---|---|---|
| Чтение ведомости «Деканата»: макет, строки «Всего», «V» → 6 | `parser.py` | `imports.StatementReader` |
| Сложение семестров (B-31): часы всех строк, приоритет экзамена, курсовая отдельно | `parser.py` | `imports.SemesterRecords` |
| З.е. из учебного плана, оба формата плана | `curriculum.py` | `imports.Curriculum` |
| Пометки для оператора о з.е. | `parser.settle_credits` | `imports.CreditCheck` |
| Учебный план в PDF, шапка плана | новое, в текущем сервисе нет | `imports.PlanPdf`, `plans.PlanTitle` |
| Структура плана, контрольные суммы, сравнение, редакции | новое | `plans.PlanStructure`, `plans.PlanCheck`, `plans.PlanDiff`, `storage.Curricula` |
| Проверки сведений, сопоставление студентов, XML 3.5.1 | `xml_generator.py` | `export.PivotSource`, `export.CyberDiplomaXml` |
| Чтение сведений о студентах | `xml_generator.py` | `export.StudentInfo` (общее у сводной и выпуска) |
| Шапка ведомости: форма, номер студента, год набора | новое | `imports.StatementReader` |
| Выпуск: сопоставление с планом, картотека, проверка, XML из картотеки | новое, вместо `parse_discipline` и `match_row` | `graduation.*`, `catalog.Checks`, `storage.Graduations`, `export.CatalogSource`, `export.ProgramFields` |

Намеренно **не перенесено** сопоставление строк ведомости со «Списком дисциплин» (`parse_discipline`, `match_row`). Это эвристика по подстрокам, и из неё выросли ошибки текущего сервиса. В новой системе строки ведомости сопоставляются с учебным планом в промежуточной зоне, а оператор подтверждает результат ([ADR-0004](architecture/adr/0004-import-staging-area.md), [ADR-0009](architecture/adr/0009-graduations-matching-registry.md)). Факультативы определяются по разделу факультативов учебного плана, а не по списку дисциплин.

### Как проверен перенос

- **128 тестов** на JDK 11: 44 сценария перенесены из Python-тестов (13 — ведомость и з.е., 31 — XML), остальные новые — печать, хранилище, HTTP с кириллическими именами файлов, учебный план в PDF, структура и суммы плана, редакции, страницы планов.
- **Проверка поломками.** В копию кода по очереди вносились ошибки: убран приоритет экзамена, отключена поправка калибровки, государственный экзамен поставлен после ВКР, имена файлов читались в ISO-8859-1. Каждую поломку тесты поймали. Удаление явной настройки UTF-8 тесты не заметили, и это верно: Tomcat 10.1 и без неё читает имена в UTF-8.
- **Сверка с Python на реальных данных** (локально, данные никуда не передавались). Обе реализации прогнаны по всем 93 книгам архива 2019–2026:
  - 105 разборов ведомостей: 4 ведомости без плана и с каждым из 3 планов (172 листа студентов, 748 строк, 712 проверок з.е.), плюс сообщения об ошибке на книгах другого вида;
  - 93 чтения учебного плана;
  - 60 пар «сводная × сведения»: 4 готовых XML общим объёмом 438 тыс. символов и 56 списков ошибок.

  Расхождений нет, XML совпали побайтно.

Повторить сверку (нужны виртуальные окружения текущего сервиса):

```sh
mvn -DskipTests package test-compile
java -cp target/open-diplom.jar:target/test-classes org.opendiplom.tools.RegressionDump statement list.txt > java.jsonl
python tools/regression/python_dump.py <путь к diploma_supplement_service> statement list.txt > python.jsonl
python tools/regression/compare.py python.jsonl java.jsonl
```

В `list.txt` — пути к файлам, по строке на прогон (для ведомости с планом — два пути через табуляцию). Выгрузки содержат персональные данные: храните их только на машине, где лежат файлы.

## Учебный план в PDF

Учебные планы приходят в основном в PDF, сохранённом из «Планов». В таком PDF есть текст, но нет ячеек: только буквы с координатами и линии сетки. Длинное название переносится на две–четыре строки выше и ниже строки с индексом, и промежуток между этими строками такой же, как между соседними строками таблицы. Поэтому по одному тексту строки таблицы не восстановить, и `PlanPdf` читает её по сетке:

- строки таблицы — промежутки между горизонтальными линиями, колонки — между вертикальными;
- под заголовками колонки пронумерованы (1 — индекс, 2 — название, …), но стоят в разных планах по-разному. Поэтому з.е. берутся из первой колонки под заголовком «в зачетных единицах», а название — из колонки под «Структура ОП»;
- повёрнутые заголовки колонок семестров («Экзамены», «Контактная работа») пропускаются;
- итоги блоков («Блок 1. Дисциплины (модули)») не берутся: у них нет индекса, а в Excel-версии плана их нет в колонке названий. Так один и тот же план даёт одинаковые з.е. в обоих форматах;
- шапка (`PlanTitle`) читается одинаково из PDF и из Excel.

Проверка на файлах из архива (локально):

- прочитаны все 5 PDF-планов с текстом (2023–2026, бакалавриат и магистратура, очная и заочная формы), шапка разобрана во всех;
- два плана бакалавриата сверены с Excel-планами тех же профилей, но на год раньше (2021 г.п. против 2022 г.п.): совпали 51 из 51 и 59 из 59 з.е. Для магистратуры Excel того же плана нет, поэтому её PDF сверен построчно с текстом файла: например, з.е. части М.1.1 в сумме дают 32, как в строке итога;
- два плана оказались сканами без текста. Их программа не принимает и прямо об этом сообщает: «похоже, это скан»;
- проверка поломками: потеря перенесённых строк, з.е. из фиксированной 8-й колонки и возврат итогов блоков — каждую поломку тесты поймали.

Ограничения: сканы не распознаются (OCR не планируется — план проще сохранить из «Планов» заново); не читаются страницы с поворотом и страницы-продолжения без строки номеров колонок. Такие случаи в архиве не встретились.

## Поля XML из учебного плана

Раньше объёмы программы оператор вписывал в форму руками для каждой программы, и в XML 2026 года это давало ошибки: у ИСТ оказались аудиторные часы и практики от ИТС, а у ИТС и ИТСм з.е. ГИА поменялись местами (B-34 в [backlog текущего сервиса](https://github.com/nikita-konkin/diploma_supplement_service/blob/main/docs/BACKLOG.md)). В напечатанные приложения ошибки не попали, их исправили вручную. Теперь поля заполняются из плана:

| Поле | Откуда |
|---|---|
| направление, профиль, квалификация, форма | шапка плана (`PlanTitle`); наименование направления переводится из прописных в обычное предложение, квалификация и форма — строчными, как в XML и приложениях прошлых лет |
| срок обучения | нормативный срок очной формы при любой форме: «4 года» для бакалавриата, «2 года» для магистратуры, хотя в заочных планах «4 года 6 месяцев» (решение владельца, B-35); для других уровней — срок из плана |
| председатель ГЭК | в плане его нет, оператор вписывает вручную (решение владельца) |
| объём программы | строка «ОБЪЕМ ОБРАЗОВАТЕЛЬНОЙ ПРОГРАММЫ», колонка з.е.; сверяется с суммой трёх блоков |
| аудиторные часы | та же строка, колонка «Контактная работа»; берутся, только если часы строки сходятся: всего = экзамены + занятия, занятия = контактная + самостоятельная |
| з.е. практик, з.е. ГИА | итоги «Блок 2» и «Блок 3» |

В PDF итоговая строка состоит из двух строк: сверху подписи над объединёнными ячейками, снизу числа. Поэтому число в колонке берётся из той строки текста, где колонку ограничивают линии сетки.

Проверка: на пяти планах 2023–2026 годов (PDF и Excel, очные и заочные, бакалавриат и магистратура) все четыре числа совпали с напечатанными приложениями и XML. В плане старого формата (2021) итогов нет: программа заполняет что нашла, а о ненайденном пишет над формой.

## Учебные планы в базе

Решение — [ADR-0008](architecture/adr/0008-curricula-by-editions.md). Что сделано:

- **Разбор всех колонок плана.** Раньше читались только з.е. и итоги. Теперь и PDF, и Excel читают колонки 3–15:
  - семестры экзаменов, зачётов, зачётов с оценкой, КП и КР;
  - з.е. всего, на экзамены и на занятия;
  - пять колонок часов.

  В Excel колонки находятся по строке номеров, как в PDF, а индекс отделён от названия. Служебные строки под итогом («Количество часов в неделю…») не читаются.
- **Структура** (`plans.PlanStructure`):
  - родитель строки — строка с самым длинным индексом-префиксом;
  - раздел определяется по блоку, факультативы — по своему заголовку;
  - листья — то, за что ставится оценка;
  - альтернативы электива — по « / » в скобках;
  - печатное имя практики — «Вид (тип)»: «Производственная практика (преддипломная практика)». Если тип уже называет вид, как в «Учебная практика (ознакомительная)», вид не повторяется.
- **Контрольные суммы** (`plans.PlanCheck`): в строке, в структуре (строка = сумма вложенных) и объём = сумма блоков 1–3. Неверное число в элементе показывается один раз — у строки над ним.
- **Сравнение** (`plans.PlanDiff`): элементы сопоставляются по печатному имени, поэтому перенумерованный элемент остаётся тем же.
- **Хранение** (`storage.Curricula`, миграция V2): программа, редакции плана, строки, журнал. Повторная загрузка того же файла не создаёт редакцию.
- **Страницы** `/plans`: список, загрузка → предпросмотр с подтверждением шапки → сохранение, редакция с итогами, суммами, сравнением, таблицей и журналом, правка, «Создать на основе».

Проверка на реальных планах (локально):

- **Контрольные суммы.** 5 PDF и 2 Excel загружены через страницы, у всех суммы сходятся.
  - Одно ложное срабатывание нашлось и исправлено: у «Части, формируемой участниками» не сходились часы ровно на 328. Это элективы по физической культуре: часы у них есть, а з.е. нет, и «Планы» не включают их в сумму части. Теперь строка без з.е. в суммы не входит.
  - Единственное оставшееся предупреждение — пустая строка «Технологическое предпринимательство» в ИТСм (заголовок модуля без чисел).
- **Excel и PDF одного плана** совпали построчно по всем колонкам.
- **ИТСм 2023 и 2024 годов** совпали целиком.
- **Сравнение очного и заочного ИТСм** показало сдвиг семестров на один и аудиторные часы 820 → 122.
- **Повторная загрузка** того же PDF распознана как «уже загружен».
- **Скан** отклонён с подсказкой про «Создать на основе».
- **Приёмка скана.** Заочный ИТС 2021 есть только сканом. Он создан на основе очного 2021:
  - технологическая практика сведена в одну строку на 9 з.е. с зачётом с оценкой в 6 и 8 семестрах, «рассредоточенная» строка удалена;
  - в итоговую строку вписаны контактные 442 и самостоятельные 7442 часа.

  Суммы сходятся. Сравнение показывает ровно эту правку и контактные часы. Все 55 элементов совпали со сканом: 54 значения з.е. и физкультура без з.е.
- **Проверка поломками.** Тесты поймали:
  - включение строк без з.е. в суммы;
  - родителя без точки после индекса: второй «Б.3.1.1» уходил под первый;
  - перенос контактных часов в план другой формы.

  Не поймано удаление явного лимита параметров формы, и это верно: у Tomcat 10.1.60 по умолчанию 10 000, форма плана из 70 строк — около 1200 полей. Настройка оставлена, чтобы обновление Tomcat с меньшим значением по умолчанию не обрезало длинные планы молча. Тест на форму из 1500+ полей это страхует.

Ограничения:

- семестры в «Создать на основе» переносятся как есть, а у заочной формы их нумерация другая. Для приложения семестры не нужны, но в плане их стоит поправить по документу;
- печатные имена практик и выбор альтернативы электива используются при сопоставлении с ведомостью (этап B, ниже).

## Выпуск и картотека

Решение — [ADR-0009](architecture/adr/0009-graduations-matching-registry.md). Что сделано:

- **Шапка ведомости** (`imports.StatementReader`): форма обучения из C1, номер студента из H1, курс и даты первой сессии из строк 4–5. Год набора = учебный год первой сессии − (курс − 1). Если у листов группы разные форма или год, это показывается до сопоставления.
- **Сведения о студентах** (`export.StudentInfo`) читаются одинаково для сводной и для выпуска. Новая необязательная колонка «ОценкаГосэкзамен» — оценка за госэкзамен, её нет в сведениях 2026 года.
- **Студенты** (`graduation.StudentMatch`): совпало, выбрано вручную, нет в ведомости, нет в сведениях, неоднозначно, не включать в выпуск. Выбор оператора привязан к ФИО и переходит в следующую загрузку группы: ведомость часто приходит раньше, чем выставлены все оценки, и группу загружают ещё раз.
- **Предметы** (`graduation.SubjectMatch`): запомненная связь → то же имя → единственное вхождение → «предложено, подтвердите» → «нет в плане, выберите». Правила «Деканата», которые учитываются при сравнении имён:
  - приписка «(Элективные дисциплины …)» у выбранного электива;
  - «Вид. Тип» практики вместо «Вид (тип)»;
  - двойные пробелы, знаки препинания и буква «ё».

  Кандидаты отбираются по з.е. из часов и по курсовой.
- **Результаты** (`graduation.Results`): имя и з.е. из плана, курсовая — «(курсовая работа)» или «(курсовой проект)» по колонкам плана. Элементы без з.е. в приложение не идут.
- **Картотека** (`storage.Graduations`, миграция V3): выпуск, решения оператора, связи программы, выпускники, результаты. Повторная загрузка группы заменяет выпускников того же выпуска.
- **Проверка** (`catalog.Checks`): ошибка, «не завершено» (код 7), предупреждение.
- **XML из картотеки** (`export.CatalogSource`, `export.ProgramFields`): тот же генератор 3.5.1, поля программы из плана, председатель ГЭК со страницы выпуска.
- **Страницы** `/graduations`: список, загрузка, сопоставление с выбором оператора, страница выпуска (поля программы, председатель, выпускники, XML, журнал), карточка выпускника (сведения, ГИА, результаты, замечания).

Проверка:

- **183 теста**, из них 53 новых: шапка ведомости, сведения, сопоставление студентов и предметов, результаты, проверка, хранилище, путь от файлов группы до XML через HTTP.
- **Проверка поломками.** Тесты поймали все десять:
  - отбор кандидатов по з.е. отключён;
  - один лист ведомости отдан двум выпускникам;
  - оценка группы не засчитана её строкам;
  - повторная загрузка оставляет старых выпускников;
  - код 7 понижен до предупреждения;
  - запомненная связь забыта;
  - выбор по студентам не переходит в новую загрузку;
  - выбор привязан к номеру строки, а не к ФИО;
  - выбор по одному из двух тёзок достаётся обоим;
  - новая загрузка не заменяет выбор прежней.
- **Реальные файлы** (локально, данные никуда не передавались):
  - ИТС-51з 2026: 14 из 14 студентов, 56 из 56 предметов автоматически, у всех 240 з.е. Заочный план 2021 года есть только сканом, поэтому он создан на основе очного, как в ADR-0008.
  - XML ИТС-51з не формируется, и это правильно: в сведениях нет оценок за госэкзамен, а в ведомости — за преддипломную практику. Всё остальное сверено с XML февраля 2026 года, каждое расхождение объяснено в ADR-0009.
  - 2025: ИТС-41 — 58 из 58, ИСТ-43 — 47 из 47, ИТСм-21 — 26 из 26 предметов автоматически.
  - Повторная загрузка той же группы проходит без вопросов к оператору: 56 из 56, выпуск обновлён на месте.

Ограничения:

- документов (номер, дата выдачи, бланк) ещё нет: картотека пока заканчивается XML для КиберДиплома;
- входа в систему нет, журнал пишет что и когда, но не кто;
- решение ГЭК хранится у каждого выпускника, как в сведениях, а председатель — у выпуска.

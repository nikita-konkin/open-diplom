# Прототип на Java 11

Проверка решения [ADR-0007](architecture/adr/0007-technology-stack.md) и перенос правил из текущего сервиса ([diploma_supplement_service](https://github.com/nikita-konkin/diploma_supplement_service)). Состояние на 26.09.2026.

## Что умеет прототип

- Веб-страница на встроенном Tomcat 10.1. В настольном режиме программа слушает только 127.0.0.1 и сама открывает браузер.
- Импорт ведомости «Деканата» (`.xls` или `.xlsx`) и, по желанию, учебного плана — в Excel или в PDF, сохранённом из «Планов». Семестры складываются, з.е. берутся из плана, для оператора — таблица пометок. Результат сохраняется в промежуточной зоне SQLite.
- Шапка учебного плана: код и наименование направления подготовки отдельно от профиля (B-25), квалификация, форма и срок обучения, год набора.
- Тестовый лист калибровки принтера (PDF, A4 альбомный) с поправками вправо и вниз в миллиметрах.
- XML «ФайлОбменаКиберДиплом» 3.5.1 из сводной таблицы и сведений о студентах: переходный период, пока печатает КиберДиплом. Кнопка «Заполнить из плана» берёт 9 из 10 полей формы из учебного плана; председателя ГЭК оператор вписывает сам.

## Результаты по критериям ADR-0007

Замеры сделаны в Linux-контейнерах OrbStack на Mac (arm64 и x86-64 через Rosetta). На каждом прогоне 9 запросов: трижды импорт реальной ведомости (141 КБ) с учебным планом, тестовый лист и XML по реальной сводной.

| Критерий | Требование | Результат |
|---|---|---|
| Запуск без установки | рантайм в поставке | урезанный jlink-рантайм 51 МБ (arm64) / 56 МБ (x86-64) и программа 39 МБ |
| Время запуска | меньше 5 с | 0,3 с (arm64), 0,7 с (x86-64 через Rosetta) |
| Память | меньше 300 МБ | пик 243 МБ (arm64) и 276 МБ (x86-64) с настройками запускателя: куча 128 МБ, последовательный сборщик мусора, только компилятор C1. С настройками JVM по умолчанию — 402 МБ, поэтому запускатель их задаёт |

## Перенесённые правила

| Что | Откуда | Куда |
|---|---|---|
| Чтение ведомости «Деканата»: макет, строки «Всего», «V» → 6 | `parser.py` | `imports.StatementReader` |
| Сложение семестров (B-31): часы всех строк, приоритет экзамена, курсовая отдельно | `parser.py` | `imports.SemesterRecords` |
| З.е. из учебного плана, оба формата плана | `curriculum.py` | `imports.Curriculum` |
| Пометки для оператора о з.е. | `parser.settle_credits` | `imports.CreditCheck` |
| Учебный план в PDF, шапка плана | новое, в текущем сервисе нет | `imports.PlanPdf`, `imports.PlanTitle` |
| Проверки сведений, сопоставление студентов, XML 3.5.1 | `xml_generator.py` | `export.PivotSource`, `export.CyberDiplomaXml` |

Намеренно **не перенесено** сопоставление строк ведомости со «Списком дисциплин» (`parse_discipline`, `match_row`). Это эвристика по подстрокам, и из неё выросли ошибки текущего сервиса. В новой системе строки ведомости сопоставляются с учебным планом в промежуточной зоне, а оператор подтверждает результат ([ADR-0004](architecture/adr/0004-import-staging-area.md)). Факультативы будут определяться по блоку ФТД учебного плана, а не по списку дисциплин.

### Как проверен перенос

- **91 тест** на JDK 11: 44 сценария перенесены из Python-тестов (13 — ведомость и з.е., 31 — XML), остальные новые — печать, хранилище, HTTP с кириллическими именами файлов, учебный план в PDF.
- **Проверка поломками.** В копию кода по очереди вносились ошибки: убран приоритет экзамена, отключена поправка калибровки, государственный экзамен поставлен после ВКР, имена файлов читались в ISO-8859-1. Каждую поломку тесты поймали. Удаление явной настройки UTF-8 тесты не заметили, и это верно: Tomcat 10.1 и без неё читает имена в UTF-8.
- **Сверка с Python на реальных данных** (локально, данные никуда не передавались). Обе реализации прогнаны по всем 93 книгам архива 2019–2026:
  - 105 разборов ведомостей: 4 ведомости без плана и с каждым из 3 планов (172 листа студентов, 748 строк, 712 проверок з.е.), плюс сообщения об ошибке на книгах другого вида;
  - 93 чтения учебного плана;
  - 60 пар «сводная × сведения»: 4 готовых XML общим объёмом 438 тыс. символов и 56 списков ошибок.

  Расхождений нет, XML совпали побайтно.

Повторить сверку (нужны виртуальные окружения текущего сервиса):

```sh
mvn -DskipTests package test-compile
java -cp target/open-diplom.jar:target/test-classes org.opendiplom.tools.RegressionDump statement list.txt > java.jsonl
python tools/regression/python_dump.py <путь к diploma_supplement_service> statement list.txt > python.jsonl
python tools/regression/compare.py python.jsonl java.jsonl
```

В `list.txt` — пути к файлам, по строке на прогон (для ведомости с планом — два пути через табуляцию). Выгрузки содержат персональные данные: храните их только на машине, где лежат файлы.

## Учебный план в PDF

Учебные планы приходят в основном в PDF, сохранённом из «Планов». В таком PDF есть текст, но нет ячеек: только буквы с координатами и линии сетки. Длинное название переносится на две–четыре строки выше и ниже строки с индексом, и промежуток между этими строками такой же, как между соседними строками таблицы. Поэтому по одному тексту строки таблицы не восстановить, и `PlanPdf` читает её по сетке:

- строки таблицы — промежутки между горизонтальными линиями, колонки — между вертикальными;
- под заголовками колонки пронумерованы (1 — индекс, 2 — название, …), но стоят в разных планах по-разному. Поэтому з.е. берутся из первой колонки под заголовком «в зачетных единицах», а название — из колонки под «Структура ОП»;
- повёрнутые заголовки колонок семестров («Экзамены», «Контактная работа») пропускаются;
- итоги блоков («Блок 1. Дисциплины (модули)») не берутся: у них нет индекса, а в Excel-версии плана их нет в колонке названий. Так один и тот же план даёт одинаковые з.е. в обоих форматах;
- шапка (`PlanTitle`) читается одинаково из PDF и из Excel.

Проверка на файлах из архива (локально):

- прочитаны все 5 PDF-планов с текстом (2023–2026, бакалавриат и магистратура, очная и заочная формы), шапка разобрана во всех;
- два плана бакалавриата сверены с Excel-планами тех же профилей, но на год раньше (2021 г.п. против 2022 г.п.): совпали 51 из 51 и 59 из 59 з.е. Для магистратуры Excel того же плана нет, поэтому её PDF сверен построчно с текстом файла: например, з.е. части М.1.1 в сумме дают 32, как в строке итога;
- два плана оказались сканами без текста. Их программа не принимает и прямо об этом сообщает: «похоже, это скан»;
- проверка поломками: потеря перенесённых строк, з.е. из фиксированной 8-й колонки и возврат итогов блоков — каждую поломку тесты поймали.

Ограничения: сканы не распознаются (OCR не планируется — план проще сохранить из «Планов» заново); не читаются страницы с поворотом и страницы-продолжения без строки номеров колонок. Такие случаи в архиве не встретились.

## Поля XML из учебного плана

Раньше объёмы программы оператор вписывал в форму руками для каждой программы, и в XML 2026 года это давало ошибки: у ИСТ оказались аудиторные часы и практики от ИТС, а у ИТС и ИТСм з.е. ГИА поменялись местами (B-34 в [backlog текущего сервиса](https://github.com/nikita-konkin/diploma_supplement_service/blob/main/docs/BACKLOG.md)). В напечатанные приложения ошибки не попали, их исправили вручную. Теперь поля заполняются из плана:

| Поле | Откуда |
|---|---|
| направление, профиль, квалификация, форма | шапка плана (`PlanTitle`); наименование направления переводится из прописных в обычное предложение, квалификация и форма — строчными, как в XML и приложениях прошлых лет |
| срок обучения | нормативный срок очной формы при любой форме: «4 года» для бакалавриата, «2 года» для магистратуры, хотя в заочных планах «4 года 6 месяцев» (решение владельца, B-35); для других уровней — срок из плана |
| председатель ГЭК | в плане его нет, оператор вписывает вручную (решение владельца) |
| объём программы | строка «ОБЪЕМ ОБРАЗОВАТЕЛЬНОЙ ПРОГРАММЫ», колонка з.е.; сверяется с суммой трёх блоков |
| аудиторные часы | та же строка, колонка «Контактная работа»; берутся, только если часы строки сходятся: всего = экзамены + занятия, занятия = контактная + самостоятельная |
| з.е. практик, з.е. ГИА | итоги «Блок 2» и «Блок 3» |

В PDF итоговая строка состоит из двух строк: сверху подписи над объединёнными ячейками, снизу числа. Поэтому число в колонке берётся из той строки текста, где колонку ограничивают линии сетки.

Проверка: на пяти планах 2023–2026 годов (PDF и Excel, очные и заочные, бакалавриат и магистратура) все четыре числа совпали с напечатанными приложениями и XML. В плане старого формата (2021) итогов нет: программа заполняет что нашла, а о ненайденном пишет над формой.

## Что дальше

1. Стенды T-01…T-07, в первую очередь Windows 7 SP1 32 бит с Liberica JDK 11 x86 и Astra Linux 1.7. Там же проверить Java 17 x86 (T-02): для Java 11 многие библиотеки уже не обновляются (ADR-0007).
2. Напечатать тестовый лист (`/test-sheet.pdf`) на принтере, где печатаются бланки, и измерить отклонение.
3. Уменьшить поставку: в jar лежат нативные библиотеки SQLite для всех платформ, а нужны только Windows и Linux.
4. Модель данных картотеки и сопоставление ведомости с учебным планом в промежуточной зоне — начало MVP.
